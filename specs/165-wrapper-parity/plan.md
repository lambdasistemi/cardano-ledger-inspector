# Implementation Plan: Reusable `tx.intent` Wrapper Parity

## Context

The pinned external `cardano-ledger-wasm` package currently exposes the base
`Conway.Inspector.runLedgerOperationInput` dispatcher. The local
`libs/cardano-ledger-inspector` package is executable-only: its WASI
`app/Main.hs` calls that dispatcher and then owns the typed auxiliary-metadata
and protocol-registry enrichment introduced by #160 and #35. The native
`tx-deep-diagnosis` library and the Extism plugin import the external module
directly, so those enrichments are target-dependent despite the repository's
public architecture contract.

The local package will become a library-plus-executable. Its library will
expose `Conway.Inspector` with the same public entry point and error type. The
module will use a package-qualified import of the external module as its kernel,
delegate the request, and apply the existing pure `tx.intent` enrichment. This
keeps consumer source APIs stable while making the local package the canonical
artifact required by constitution principle V.

`app/Main.hs` retains WASI stdin/stdout/error handling and its separate
WASI-only RDF path. It package-qualifies the local `Conway.Inspector` module and
no longer contains `tx.intent` enrichment logic. The native CLI and Extism
plugin remove their direct kernel dependency and resolve `Conway.Inspector`
from the local library instead.

## Source Assembly

`Conway.Inspector.EmbeddedRegistry` remains generated by Nix from
`docs/inspector/protocols/registry.json` plus every declared blueprint and
deployment-registry file. The generator moves from the executable's `app/`
tree to the library's `src/` tree and is applied to:

1. the WASI inspector source assembled with `tx-rdf-core`;
2. the full-repository source used by the Extism build, also assembled with
   `tx-rdf-core`; and
3. the full-repository source passed to the native haskell.nix project.

The native `cabal.project` adds the local inspector package and the pinned
`tx-rdf-core` source-repository package. The Extism project lists the local
inspector and injected `tx-rdf-core` path packages. Any affected WASM fixed
dependency hashes are regenerated deliberately.

## Conformance Shape

A small native raw-envelope executable in the local package will read stdin,
call the local wrapper, and serialize success/error results with the same byte
contract as the WASI reactor. It is a test harness; `tx-deep-diagnosis` remains
the native product and independently depends on the same library.

The existing `tx-extism-spike-smoke` becomes the three-target conformance
check. It first observes RED because the Extism plugin has no `tx_intent`
export and both non-WASI targets lack the local enrichments. GREEN runs:

- a registered SundaeSwap/Amaru request with explicit producer CBOR; and
- an unknown-script request derived from the existing complete-context
  fixture.

For each request it captures WASI, native, and Extism responses and uses raw
byte comparison across all three files. It also asserts the registered
datum/redeemer/deployment annotations and unknown raw fallback, preventing an
empty or uniformly degraded response from satisfying parity.

## Constitution Check

- **III — JSON control plane, CBOR data plane**: satisfied. All targets accept
  the same explicit JSON envelope and transaction/producer CBOR and are tested
  for byte-identical JSON output.
- **V — library is canonical**: satisfied. Target entry points depend on the
  local library wrapper; the executable-only enrichment boundary is removed.
- **I and IV**: unchanged. Ledger decoding remains in upstream Haskell ledger
  packages, and producer context remains explicit request data.
